# ADR-008: Ownership-only доступ (assignee = владелец)

**Статус:** Принято  
**Дата:** 2026-09-21

## Контекст

Требование «доски с задачами закрепляются за пользователем» и два предзаполненных пользователя
не задают модель совместной работы. При этом есть фича assignee (`06-api.md`), а `GET /api/users`
возвращал всех пользователей. Если доступ к доске есть только у владельца, назначение карточки
на другого пользователя не даёт ему никакого эффекта: он не сможет открыть доску.

## Решение

- **Доступ к доске — только у владельца.** `BoardAccessGuard` пускает `board.ownerId === user.id`.
- **Assignee ограничен владельцем доски.** `PATCH /api/cards/:id/assignee` принимает
  `assigneeId: string | null`, но значение обязано равняться `board.ownerId`; иначе `422`.
- **`GET /api/users` возвращает только текущего пользователя** — это множество доступных
  исполнителей в ownership-модели (фронт показывает один вариант «На меня»).
- **Совместная работа (участники доски, шеринг) — вне скоупа.** При необходимости вводится
  таблицей `BoardMember` и расширением guard'а без изменения остальных слоёв.

## Последствия

- Модель прав тривиальна: один владелец на доску, никаких ролей.
- Cross-user назначения невозможны; seed назначает исполнителем владельца.
- Чужой ресурс отвечает `404 BOARD_NOT_FOUND`, а не `403`, чтобы не раскрывать существование
  (см. `04-backend.md`).
- Если позже потребуется коллаборация — добавляется `BoardMember`, guard проверяет
  `owner ∪ member`, `GET /api/users` возвращает участников доски.

## Альтернативы

- **`BoardMember` сразу** — rejected на этом этапе: расширяет схему, guard, API и seed без
  явного требования; добавляется позже без ломки слоёв.
- **Оставить assignee любым пользователям** — rejected: назначенный не имеет доступа к доске,
  фича не работает.
