# ADR-002: Redis (Socket.IO adapter)

**Статус:** Принято  
**Дата:** 2026-09-21

## Контекст

Redis присутствует в исходных требованиях к Docker Compose. Нужно определить его роль,
чтобы сервис не оказался «мёртвой» зависимостью.

## Решение

Redis используется как **Socket.IO Redis adapter** (`@socket.io/redis-adapter` + `ioredis`):
события доски доставляются всем подписчикам независимо от того, к какому инстансу backend
они подключены, что даёт горизонтальное масштабирование. Дополнительно Redis Pub/Sub
(`board:{boardId}:activity`) разносит записи activity между инстансами, чтобы SSE-поток
не зависел от того, где записано событие (см. `04-backend.md`).

Redis — обязательный сервис в compose с healthcheck и AOF-персистентностью (`--appendonly yes`).

## Последствия

- Backend подключает `@socket.io/redis-adapter` + `ioredis`, а также Redis Pub/Sub для SSE-activity.
- `REDIS_URL` обязателен в `serverEnvSchema` (не `.optional()`).
- Локально Redis поднимается корневым `docker-compose.yml` (`docker compose up`).
- Фоновые задачи (BullMQ) **не используются**: в требованиях нет напоминаний о дедлайнах,
  зависимость убрана из стека, чтобы не дублировать ситуацию с «мёртвыми» библиотеками.

## Альтернативы

- **Убрать Redis** — rejected: противоречит требованиям к compose и лишает горизонтального масштабирования.
- **In-memory adapter Socket.IO** — rejected: работает только на одном инстансе.
- **BullMQ для напоминаний** — rejected: функционального требования нет, отдельная фаза не заводится.
