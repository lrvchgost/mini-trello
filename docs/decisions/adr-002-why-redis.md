# ADR-002: Redis (Socket.IO adapter + фоновые задачи)

**Статус:** Принято  
**Дата:** 2026-09-21

## Контекст

Redis присутствует в исходных требованиях к Docker Compose. Нужно определить его роль,
чтобы сервис не оказался «мёртвой» зависимостью.

## Решение

Redis используется для двух задач:

1. **Socket.IO Redis adapter** — масштабирование backend на несколько инстансов:
   события доски доставляются всем подписчикам независимо от того, к какому инстансу они подключены.
2. **BullMQ** — фоновые задачи: напоминания о приближающихся и просроченных дедлайнах.

Redis — обязательный сервис в compose с healthcheck и AOF-персистентностью (`--appendonly yes`).

## Последствия

- Backend подключает `@socket.io/redis-adapter` + `ioredis`; очередь — `@nestjs/bullmq`.
- `REDIS_URL` обязателен в `serverEnvSchema` (не `.optional()`).
- Локально Redis поднимается тем же `docker/docker-compose.yml`.

## Альтернативы

- **Убрать Redis** — rejected: противоречит требованиям к compose и лишает горизонтального масштабирования.
- **In-memory adapter Socket.IO** — rejected: работает только на одном инстансе.
